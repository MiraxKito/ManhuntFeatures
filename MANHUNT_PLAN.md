# Manhunt Features — план проекта

## 1. Рекомендация по формату

Рекомендую сделать **плагин на Bukkit/Spigot API для Minecraft Java Edition**. Он будет работать на **Spigot 1.20.1 и Paper 1.20.1**; Paper остаётся рекомендуемой платформой из-за более комфортной работы с нагрузкой, но код не будет зависеть от Paper-only API.

Почему:

- роли и команды реализуются штатно через Bukkit/Spigot API;
- обработка правого клика компасом не требует установки клиента;
- отдельные Overworld/Nether/End можно создавать, выгружать и пересоздавать программно;
- плагин работает на сервере, поэтому игрокам не нужно ставить моды;
- единый Bukkit API-код проще переносить между версиями, хотя при обновлении Minecraft всё равно потребуется отдельная проверка API и поведения генерации миров.

Датапак здесь будет неудобен: сложный reset миров, безопасное удаление каталогов, управление загрузкой миров и блокировка состояния во время генерации лучше делать кодом.

Рабочее название плагина: `mhfeatures`.

> Целевая версия первой реализации: **Minecraft 1.20.1**, совместимость с Bukkit/Spigot и Paper 1.20.1. Java-версия и API будут закреплены в `build.gradle`.

## 2. Модель миров

Оригинальный мир сервера не трогаем. По умолчанию это `world`, но имя должно быть настройкой.

Плагин создаёт отдельную группу миров:

```text
world                         # оригинальный мир сервера
world_mh                       # Manhunt Overworld
world_mh_nether                # Manhunt Nether
world_mh_the_end               # Manhunt End
```

Названия будут настраиваться в `config.yml`. Плагин должен проверять, что manhunt-миры действительно принадлежат ему: рядом с ними создаётся служебный marker-файл/metadata. Это защита от случайного удаления чужих миров при `/mhfeatures reset`.

Связь измерений:

- `world_mh` имеет environment `NORMAL`;
- `world_mh_nether` имеет environment `NETHER`;
- `world_mh_the_end` имеет environment `THE_END`;
- Nether и End создаются как отдельные миры, а не как папки внутри оригинального мира;
- seed для всех трёх миров берётся из одного seed-значения через настройки генерации Paper/Bukkit.

Перенос игрока в manhunt-мир означает перенос в `world_mh` на его world spawn. Межпространственные переходы Nether portal/End portal между manhunt-мировыми парами можно поддержать отдельно, но это не должно смешивать их с оригинальными мирами.

## 3. Роли

Роли хранятся по UUID, а не по имени, чтобы переименование игрока не ломало настройки. Хранение — `roles.yml` или отдельный раздел `data.yml`.

Поддерживаемые роли:

- `HUNTER` — охотник;
- `RUNNER` — бегущий;
- `NONE` — роль снята.

Команда:

```text
/mhfeatures role <player> <hunter|runner|clear>
```

Также Paper автоматически позволит использовать namespaced-вариант:

```text
/mhfeatures:role <player> <hunter|runner|clear>
```

Поведение:

- команду могут использовать только игроки/консоль с permission `mhfeatures.admin.role`;
- для первой версии целимся в онлайн-игроков, но сохраняем роль по UUID;
- смена роли сама по себе не телепортирует игрока и не чистит инвентарь — для этого есть отдельные команды;
- при смене роли игрок получает понятное сообщение с новой ролью;
- tab-completion предлагает игроков и допустимые роли;
- в конфиге можно включить отображение роли в scoreboard/tab-list, но это не является обязательной частью первой версии.

Это позволяет иметь несколько охотников и несколько бегущих одновременно.

## 4. Компас

### Логика активации

Компас обновляет цель **только при взаимодействии игрока**, а не каждый тик.

Обрабатываем:

- правый клик в воздухе;
- правый клик по блоку;
- основной и второстепенный слот, чтобы работал обычный bind взаимодействия;
- только предмет `COMPASS`;
- только игрока с ролью `HUNTER` (настраиваемое поведение для остальных — по умолчанию без действия).

### Выбор цели

При активации плагин ищет среди игроков с ролью `RUNNER`:

- только игроков в том же manhunt-мире;
- только игроков в том же измерении;
- расстояние считается от текущей позиции охотника;
- выбирается ближайший бегущий;
- учитываются только онлайн-игроки.

Плагин записывает в compass target охотника координаты выбранного бегущего, но игрок видит только направление стрелки компаса. Координаты в сообщениях, action bar, названии предмета и lore не показываются. Это именно последняя точка на момент клика: если бегущий продолжит движение, стрелка не будет автоматически обновляться.

Если подходящего бегущего нет, например он находится в Nether/End, игрок получает:

```text
Нет игроков для отслеживания.
```

В этом случае старую цель лучше сбрасывать, чтобы компас не продолжал показывать устаревшего игрока. Текст сообщений и cooldown на использование — настройки.

Дополнительные ограничения первой версии:

- компас не работает для охотника в оригинальном мире, если там нет manhunt-цели;
- spectator/vanished-игроки не считаются целями, если это включено в конфиге;
- при смерти, смене измерения или смене роли цель не обновляется автоматически — новое нажатие делает новый снимок.

## 5. Аргументы игроков и селекторы

Обозначение `<player>` означает аргумент выбора игроков. Команды поддерживают:

- ник одного игрока, например `Steve`;
- `@s` — самого себя, если команду выполняет игрок;
- `@a` — всех онлайн-игроков;
- `@p` — ближайшего игрока;
- `@r` — случайного игрока;
- `@e[type=player]` и другие стандартные player-селекторы Bukkit/Spigot, если серверная версия и синтаксис их поддерживают.

Если аргумент игрока не указан, команда использует самого отправителя (`@s`). Для консоли отсутствие аргумента считается ошибкой, потому что у консоли нет собственного игрока.

Селектор может вернуть группу игроков. Например, `/mhfeatures ogworld @a` переносит всех выбранных игроков. Операция применяется к каждому выбранному игроку, а ошибки по одному игроку не должны молча скрывать ошибки по остальным.

## 6. Перемещение между мирами

Команды:

```text
/mhfeatures mhworld [player]
/mhfeatures ogworld [player]
```

Namespaced-варианты также будут работать:

```text
/mhfeatures:mhworld <player>
/mhfeatures:ogworld <player>
```

`mhworld`:

- переносит игрока в `world_mh` на его spawn;
- если manhunt-миры ещё не созданы, сообщает об ошибке и предлагает выполнить reset/инициализацию;
- не меняет роль и не чистит инвентарь.

`ogworld`:

- переносит игрока в оригинальный мир на обычный world spawn;
- не использует личную последнюю позицию, чтобы команда всегда была предсказуемой;
- не меняет роль.

Обе команды защищаются permission-узлами и блокируются во время reset.

При необходимости позже можно добавить отдельные команды для переноса группы или всех игроков, но в первую версию достаточно указанного интерфейса.

## 7. Сброс manhunt-миров

Команда:

```text
/mhfeatures reset [seed]
```

Seed необязателен:

- без seed — использовать новый случайный seed или seed из конфигурации, согласно настройке;
- с seed — использовать указанное числовое значение и создать предсказуемый мир;
- строковые seeds можно поддержать позже, если это потребуется, но числовой seed проще сделать однозначным для первой версии.

### Безопасный порядок операции

1. Проверить permission и что reset не выполняется сейчас.
2. Включить глобальное состояние `RESETTING`.
3. Запретить все команды плагина, повторный reset, переносы и взаимодействия с компасом.
4. Сообщить всем игрокам, что начался reset и сервер временно занят.
5. Перенести всех игроков из manhunt-миров в оригинальный мир на world spawn.
6. Очистить инвентарь, броню, offhand и при необходимости ender chest у всех игроков — это должно быть явно закреплено настройкой. Базовое решение: чистить инвентарь, броню и offhand; ender chest не трогать, если отдельно не включено.
7. Очистить временные compass targets и runtime-состояние.
8. Корректно выгрузить три manhunt-мира.
9. Удалить только подтверждённые plugin-owned каталоги старых manhunt-миров. Оригинальный мир никогда не удалять.
10. Создать новый Overworld, Nether и End с выбранным seed.
11. Пометить новые миры как принадлежащие плагину.
12. Снять `RESETTING`, сохранить состояние и сообщить об успешном завершении.

### Нагрузка и защита

Генерация чанков Minecraft в любом случае может быть тяжёлой и частично выполняться на серверном потоке. Поэтому нельзя обещать «полностью без лагов». Плагин должен:

- не пытаться удалять/создавать миры в нескольких параллельных задачах;
- показывать этап операции и понятное предупреждение;
- блокировать команды и действия, которые могут сломать состояние;
- корректно восстанавливаться после перезапуска сервера во время reset: при старте проверять lock/state-файл и не продолжать опасное удаление вслепую;
- по возможности создавать миры по очереди и не запускать лишний pre-generation в первой версии;
- опционально иметь `pregenerate-radius`, отключённый по умолчанию, для подготовки области до начала игры.

Если удаление старого мира или создание нового мира не удалось, плагин не должен продолжать молча. Он оставляет оригинальный мир нетронутым, пишет подробную ошибку в консоль и сообщает игрокам, что reset не завершён.

## 7. Команды и права

Предлагаемая структура прав:

```text
mhfeatures.admin.role
mhfeatures.admin.reset
mhfeatures.admin.mhworld
mhfeatures.admin.ogworld
mhfeatures.admin.reload
mhfeatures.use.compass
```

Команды первой версии:

```text
/mhfeatures role <player> <role>
/mhfeatures reset [seed]
/mhfeatures mhworld <player>
/mhfeatures ogworld <player>
/mhfeatures status
/mhfeatures reload
```

`status` полезен для диагностики: показывает состояние reset, наличие миров, seed и число охотников/бегущих.

Команды `/reload` сервера поддерживать не нужно: Paper reload часто создаёт проблемы с плагинами. Используем только собственный `/mhfeatures reload`, который перечитывает безопасные настройки.

## 8. События и защита от краевых случаев

Нужно предусмотреть:

- игрок вышел во время reset;
- игрок вошёл, пока reset ещё идёт;
- игрок находится в удаляемом мире при ошибке;
- бегущий умер, вышел или сменил измерение;
- охотник использует компас в оригинальном мире;
- мир уже существует при старте плагина;
- часть manhunt-миров отсутствует;
- две команды reset вызваны почти одновременно;
- сервер перезапустился после выгрузки, но до генерации новых миров;
- у команды нет permission;
- указан неизвестный игрок или неизвестная роль.

На старте плагина выполняется проверка конфигурации и состояния миров. Автоматически удалять подозрительные папки по совпадению имени нельзя.

## 9. Конфигурация

Примерный `config.yml`:

```yaml
original-world: world
manhunt:
  overworld: world_mh
  nether: world_mh_nether
  end: world_mh_the_end
  seed-mode: random # random | configured
  seed: 0
  clear-ender-chest-on-reset: false
compass:
  hunter-only: true
  message-no-target: "Нет игроков для отслеживания."
  cooldown-ticks: 0
  ignore-vanished: true
reset:
  block-all-plugin-commands: true
  teleport-to-original-spawn: true
  clear-inventory: true
  clear-armor: true
  clear-offhand: true
  pregenerate-radius: 0
messages:
  prefix: "[Manhunt] "
```

Секреты и внешние сервисы не нужны.

## 11. Что не включаем в первую версию

Чтобы не превратить плагин в неуправляемый комбайн, пока не включаем:

- автоматическое определение победы и завершение игры;
- GUI для распределения ролей;
- автоматический постоянный трекинг компаса;
- синхронизацию инвентарей между оригинальным и manhunt-миром;
- базы данных и внешние сервисы;
- клиентский мод;
- полную защиту от всех серверных команд во время reset — блокируем команды плагина и опасные действия, а список сторонних команд делаем настраиваемым.

Автоматическое завершение игры можно добавить после того, как базовая модель миров и ролей будет проверена на реальном сервере.

---

## 12. Критерии готовности

Проект считаем готовым к тестированию, если:

- плагин запускается на чистом Paper-сервере без ошибок;
- роли сохраняются по UUID и работают с несколькими охотниками/бегущими;
- компас меняет цель только после клика и выбирает ближайшего бегущего в том же измерении;
- при отсутствии цели выводится «Нет игроков для отслеживания.»;
- `mhworld` и `ogworld` работают для выбранного игрока;
- reset переносит игроков, чистит согласованный набор инвентаря, удаляет только свои миры и создаёт новые;
- оригинальный мир и его spawn остаются нетронутыми;
- команды блокируются во время reset;
- отсутствующие/повреждённые миры обрабатываются с ошибкой, без опасного удаления;
- после перезапуска сервера роли и конфигурация не теряются;
- команда `status` позволяет понять состояние системы без чтения логов.
